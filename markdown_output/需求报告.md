2.2 项目背景
浙江大学软件工程基础课程在内容上分为理论课和实验课两大部分。理论课由老师介绍软件工程中的相
关理论知识，实验课采取分组完成形式，每5人组成1小组，每5小组组成1大组，合作进行软件系统开
发。本学期课程中老师选择股票交易系统作为综合性实验题目。

本交易客户端是股票交易系统综合实验项目的核心前端交互子模块。该实验旨在通过模拟真实的股票交
易流程，使学生深入理解金融信息系统，特别是交易前端的业务逻辑、人机交互设计及与后台系统的数
据通信机制。交易客户端作为投资者直接使用的终端，其稳定性、易用性和实时性是系统成功的关键。


2.3 项目目标
交易客户端子模块的核心目标是：为投资者提供一个安全、便捷、实时的股票交易操作平台。用户通过
该客户端，可以完成身份认证，全面掌握个人资产状况，实时获取市场行情，并高效、准确地下达买卖
指令、管理订单及查看交易结果。具体目标包括：

 1. 实现安全的用户登录与身份验证。

 2. 提供清晰的证券持仓与资金账户信息查询视图。

 3. 支持便捷的股票信息查询与行情展示。

 4. 实现买入、卖出、撤单等核心交易指令的发起与管理。

 5. 实时反馈指令状态与成交结果，并更新本地数据。


2.4 项目用户
本交易客户端子模块的预期用户包括：

 1. 投资者：交易客户端的主要使用者。包括个人投资者和机构投资者。他们通过客户端登录系统，查
  询股票信息和个人资产，下达买卖指令，并管理自己的投资组合。

 2. 证券经纪商：间接用户。投资者通过经纪商提供的渠道（如营业部设备、指定网站）使用本客户
  端，经纪商需要确保客户端与其后台系统稳定对接，并为投资者提供使用支持。

 3. 系统管理员：负责交易客户端软件的部署、升级、基础参数配置（如连接服务器地址）及运行监
  控。


3. 需求说明
3.1 整体需求
交易客户端是股票交易系统的核心用户交互模块，负责投资者与中央交易系统之间的指令传递与信息展
示。系统需支持以下整体需求：

 1. 登录验证：系统需要提供资金账户卡号与密码的验证功能，支持首次登录时的安全证书认证，确保
  只有合法用户能够进入交易界面。

 2. 股票查询：系统需要提供股票信息查询功能，用户可通过输入股票名称或代码查询最新成交价、当
  日/本周/本月最高最低价、当前最优买卖报价及股票公告。

 3. 持仓查询：系统需要提供证券账户持仓查询功能，展示投资者持有的所有股票名称、代码、总股
  数、当前市场价格、持有成本及持有损益。

 4. 资金查询：系统需要提供资金账户信息查询功能，展示可用资金与冻结资金。

 5. 购买指令：系统需要提供股票购买功能，用户输入股票代码、购买价格和数量，系统给出参考价并
  验证可用资金是否充足。

3.3 性能需求
 1. 实时性：股票价格及报价信息刷新频率不低于每 5 秒一次。

 2. 响应速度：单用户操作下，界面响应时间小于 1 秒；指令提交响应时间小于 2 秒。

 3. 并发支持：系统至少支持 500 个用户同时在线进行交易操作。

 4. 多端支持：系统需支持刷卡设备端与网络浏览器端两种接入方式。



3.4 安全性需求
 1. 用户登录需通过资金账户卡号与交易密码双重验证；首次登录需完成安全证书认证。

 2. 密码错误超过规定次数后账户应予以锁定。

 3. 购买指令提交前须验证资金账户可用余额；出售指令提交前须验证证券账户持仓数量。

 4. 密码在传输与存储时应加密处理，防止 SQL 注入与暴力破解。
